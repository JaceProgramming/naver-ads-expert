# 파워링크 클릭 후 사이트가 열리지 않을 때 해결 방법이 궁금해요.

광고를 클릭하였을 때 사이트가 정상적으로(혹은 의도대로) 열리지 않는 경우와 그 해결방안에 대해 알아봅니다.

-   **광고주 웹 서버에서 한글 URL을 잘못 해석하여 사이트가 정상적으로 열리지 않는 경우**
    
-   네이버 검색광고에서는 연결 URL의 도메인과 호스트 부분을 제외한 다른 부분은 EUC\_KR로 인코딩 합니다.
    
-   예를 들어 연결 URL이 '[https://www.모터스-abc.com/](https://www.%EB%AA%A8%ED%84%B0%EC%8A%A4-abc.com/%EB%AA%A8%EB%8D%B8A/list.html?kwd=%EB%AA%A8%EB%8D%B8A)[모델A](https://www.%EB%AA%A8%ED%84%B0%EC%8A%A4-abc.com/%EB%AA%A8%EB%8D%B8A/list.html?kwd=%EB%AA%A8%EB%8D%B8A)[/list.html?kwd=](https://www.%EB%AA%A8%ED%84%B0%EC%8A%A4-abc.com/%EB%AA%A8%EB%8D%B8A/list.html?kwd=%EB%AA%A8%EB%8D%B8A)[모델A](https://www.%EB%AA%A8%ED%84%B0%EC%8A%A4-abc.com/%EB%AA%A8%EB%8D%B8A/list.html?kwd=%EB%AA%A8%EB%8D%B8A)'와 같은 경우, '모델A'로 된 두 부분은 시스템이 바로 인식하지 못하기 때문에 '%EB%AA%A8%EB%8D%B8A'와 같이 변환되며, 변환된 URL로 클라이언트가 광고주 웹 서버에 접속합니다 (위의 경우 '/모델A/list.html?kwd=모델A' 부분은 '/%EB%AA%A8%EB%8D%B8A/list.html?kwd=%EB%AA%A8%EB%8D%B8A'와 같이 변환됩니다).
    
-   광고주 웹 서버에서 이 부분을 제대로 인식을 못하면 사이트가 정상적으로 열리지 않을 수 있습니다.
    
    -   **해결 방안**: 변환된 하위 디렉터리 부분을 EUC\_KR로 해석하도록 웹 서버의 설정을 변경합니다.
        

-   **URL에 추가된 파라미터와 값을 웹 사이트에서 제대로 인식하지 못하여 사이트가 정상적으로 열리지 않는 경우**
    
-   광고주 웹 사이트에서 도메인 혹은 하위 디렉터리에 붙은 파라미터와 값을 제대로 해석하지 못하여 사이트가 정상적으로 열리지 않는 경우가 있습니다.
    
-   예를 들어 '[https://www.naver.com](https://www.naver.com/)'과 같은 사이트가 있다고 할 경우 '[https://www.naver.com?a=b](https://www.naver.com/?a=b)'와 같이 입력하면 사이트가 정상적으로 열리지 않는 경우가 있습니다.
    
-   열리지 않는 경우 예)
    
-   [https://www.naver.com?a=b](http://www.naver.com/?a=b)
    
-   [https://www.naver.com/sub/?a=b](https://www.naver.com/sub/?a=b)
    
    -   **해결 방안**: 웹 서버에서 위와 같은 형태의 파라미터와 값도 정상적으로 열리도록 웹 서버의 설정을 변경합니다.
        

-   **네이버 검색광고에서 제공하는 자동 추적 기능의 추적 파라미터의 인코딩 방식을 잘못 알고 있는 경우**
    
-   자동 추적 기능을 통해 전달되는 값의 한글은 UTF-8 방식으로 인코딩됩니다.
    
-   예를 들어 추적 URL(파라미터)의 실제 내용이 'n\_keyword=여성의류&n\_query=여성의류'와 같다면 실제 전달되는 URL은 'n\_keyword=%EC%97%AC%EC%84%B1%EC%9D%98%EB%A5%98&n\_query=%EC%97%AC%EC%84%B1%EC%9D%98%EB%A5%98'과 같이 변환됩니다.
    
-   위 변환된 URL부분을 UTF-8이 아닌 다른 방식으로 디코딩하는 경우 서버 오류(보통 HTTP 500 오류)가 발생하면서 사이트가 정상적으로 열리지 않을 수 있습니다..
    
    -   **해결 방안**: 자동 추적 기능으로 제공되는 값은 모두 UTF-8로 인코딩되어 있으므로, UTF-8로 디코딩합니다.
        

-   **광고주 웹서버(혹은 방화벽)가 긴 URL을 받아들이지 못하는 경우**
    
-   간혹 전환 추적을 사용하거나 자동 추적 기능을 사용하여 URL이 길어질 때, URL을 광고주 웹 서버 혹은 보안 관련 시스템(예: 방화벽 등)이 해킹시도로 의심하여 거부하는 경우가 있으며, 이 때 사이트가 제대로 열리지 않을 수 있습니다.
    
    -   **해결 방안**: URL의 길이는 연결 URL이 길거나, 자동 추적 기능 사용으로 한글이 변환되는 경우, 전환 추적 사용 등에 의해 길어질 수 있습니다. 따라서 웹 서버 혹은 보안 관련 시스템이 최소 1,024바이트는 받아들일 수 있도록 설정합니다.
        

-   **광고주 웹 서버(혹은 방화벽)가 긴 referrer를 받아들이지 않는 경우**
    
-   네이버 통합검색에서 HTTPS를 적용함에 따라 참조 주소를 나타내는 환경 변수 인 HTTP \[REFERRER\]의 값이 길어졌습니다. 이렇게 HTTP \[REFERRER\]의 값이 길어짐에 따라 이를 광고주 웹 서버 혹은 보안 관련 시스템(예: 방화벽 등)이 해킹 시도로 의심하여 연결을 거부하는 경우가 있으며, 이때 사이트가 제대로 열리지 않을 수 있습니다.
    
    -   **해결 방안**: 광고주 웹 서버 혹은 보안 관련 시스템이 HTTP \[REFERRER\]를 최소 4,000바이트는 받아들일 수 있도록 설정합니다.
